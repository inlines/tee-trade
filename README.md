# Tee Trade

Стартовый каркас магазина футболок: Angular 21, Rust (Axum), PostgreSQL 17,
Redis 7, Prometheus и Grafana. Каждый сервис запускается в отдельном контейнере.

## Запуск

Нужен Docker с Compose v2.

Docker-сборка использует кеш BuildKit: Cargo сохраняет скачанные зависимости и
скомпилированные библиотеки между сборками, npm — скачанные пакеты. Слой `npm ci`
переиспользуется, пока не изменились `package.json` или `package-lock.json`.
Rust-кеш сборки разделён по архитектуре и версии компилятора; исполняемый файл
копируется из кеша в образ отдельно. Первая сборка после этого изменения ещё
будет полной — ускорение появится при последующих обновлениях на том же сервере.
Кеш локален для Docker builder; очистка build-кеша потребует прогрева заново.

Обновление уже запущенного проекта (существующий `.env` сохраняется):

```sh
git pull --ff-only origin main
docker compose up -d --build
```

```sh
cp .env.example .env
# Задайте ADMIN_PASSWORD в .env перед первым запуском
docker compose up --build -d
```

- Магазин: http://localhost:4200
- API: http://localhost:8080/api/products
- Проверки: `/health` (процесс), `/ready` (PostgreSQL)
- Метрики API: http://localhost:8080/metrics
- Prometheus: http://localhost:9090
- Grafana: http://localhost:3000 — пользователь `admin`, пароль из `.env`.

В Grafana автоматически создаются источник Prometheus и дашборд Tee Trade API.
Счётчик `http_requests_total` содержит метки route и status.
Миграции выполняются при старте backend и добавляют демонстрационные товары.
Цены хранятся целым числом в копейках. Каталог кешируется в Redis на 60 секунд;
при недоступности кеша API читает PostgreSQL.

## Разработка

```sh
# Инфраструктура
docker compose up -d postgres redis prometheus grafana
# Backend (Rust 1.91+), из backend/
DATABASE_URL=postgres://user:password@localhost:5432/tee_trade REDIS_URL=redis://localhost:6379 RUST_LOG=info cargo run
# Frontend (Node.js 22.12+), из front/
npm ci
npm start
```

PostgreSQL и Redis по умолчанию доступны только в сети Compose. Для локального
backend добавьте проброс `127.0.0.1:5432:5432` и `127.0.0.1:6379:6379` в локальный
`compose.override.yaml` (он не должен содержать секретов). Подставьте параметры из `.env`.
Фронтенд перенаправляет `/api` на localhost:8080 через dev proxy.

```sh
# Проверки
cd backend
cargo fmt --check
cargo check --locked
# Из front/
npm run build
# Из корня
docker compose config -q
docker compose logs -f
docker compose down
```

Данные PostgreSQL, Prometheus и Grafana сохраняются в именованных томах.
`docker compose down -v` удаляет эти данные.
`.env` не коммитится. Пароли из примера предназначены для локального запуска.
Это стартовый каталог; корзина, заказы, платежи и авторизация пока не реализованы.

## Страницы и каталог

- `/` — главная с разделами и подборкой товаров.
- `/catalog` — весь каталог; `/catalog/sneakers`, `/catalog/t-shirts`,
  `/catalog/accessories`, `/catalog/headwear` — отдельные категории.
- `/product/:id` — описание, характеристики и галерея товара.
- `/about` — о проекте.

Общее меню доступно на каждой странице. В каталоге можно сортировать по цене
и году выпуска. Карточка показывает одно основное изображение; на странице
товара доступны все изображения и отдельная кнопка просмотра ярлычка.

API: `GET /api/products?category=sneakers`, `GET /api/products/:id`.
Неизвестная категория возвращает 400, отсутствующий товар — 404.
Миграция `0002_catalog.sql` добавляет характеристики, категории и JSONB-галерею.
Каждое изображение имеет `url`, `alt` и `kind` (`front`, `detail`, `label`).
После миграции `0004_optional_products.sql` фотографии и подписи необязательны.
База проверяет структуру изображений и непустые ссылки. Админка проверяет наличие загруженного файла, формат и размер. Администратор
назначает роль «Ярлычок» и проверяет содержание снимка.

Сейчас каталог содержит **демонстрационные товары и SVG-иллюстрации**.
Они помечены `is_demo`; шаблон ярлычка не является фотографией реального изделия.
Демо-иллюстрации находятся в `front/public/images/`. Реальные фотографии загружаются через `/admin` и сохраняются в базе; фото ярлычка необязательно.

После обновления запустите `docker compose up --build -d` — миграция применится
автоматически к существующей базе. Старые тома удалять не нужно.

Интеграционная проверка запущенного приложения:

```sh
python3 scripts/smoke_test.py
```

Проверяются категории, поля и галереи товаров, доступность локальных изображений,
ответы 400/404 и открытие внутренних страниц напрямую через nginx.

Проверка ограничений галереи (изменения откатываются):

```sh
docker compose exec -T postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -v ON_ERROR_STOP=1' < scripts/check_gallery.sql
```

## Администрирование

Адрес: http://localhost:4200/admin. Ссылки на админку нет в публичном меню.
В системе один администратор: логин задаётся через `ADMIN_USERNAME` (по умолчанию
`arzamas`), начальный пароль — через `ADMIN_PASSWORD` в локальном `.env`.
Пароль не записывается в исходники или миграции. При первом старте сохраняется
Argon2id-хеш в PostgreSQL. При следующих стартах существующий аккаунт сохраняется:
изменение `.env` не меняет пароль уже созданного администратора.

После входа доступны:

- добавление и редактирование товаров со всеми характеристиками;
- удаление товаров с подтверждением: товар убирается из каталога и подборок главной, опустевшие подборки отключаются; фотографии удаляются из базы вместе с товаром, кроме используемых другими товарами;
- загрузка до 12 фотографий, выбор основного фото, ярлычка, подписей и порядка;
- выбор и порядок товаров в верхней галерее и популярной подборке;
- заголовки, категории и текстовый блок главной, включение/выключение разделов.

Файлы JPEG, PNG и WebP до 8 МБ проверяются декодером, ориентируются по EXIF,
уменьшаются до 2400 пикселей по большей стороне и сохраняются как JPEG в таблице
`media`. Фотографии сохраняются вместе с томом PostgreSQL; отдельного каталога
на хосте не требуется. Удаление фото из формы отсоединяет его от товара; сам файл
остаётся в хранилище. При резервном копировании БД сохраняются и изображения.

Сессия действует 8 часов, хранится в HttpOnly / SameSite=Strict cookie и отзывается
при выходе. Все административные операции защищены серверной проверкой сессии,
изменения — CSRF-токеном. После 15 попыток входа за 5 минут новые попытки временно
блокируются (общий лимит для единственного администратора).
Для HTTPS-развёртывания задайте `COOKIE_SECURE=true` и `APP_ORIGIN` равным точному
адресу сайта. Локально используется `http://localhost:4200`.

Редактирование товара обновляет версию кеша каталога в той же транзакции.
Главная получает содержимое через `GET /api/storefront`; настройки сохраняются
в PostgreSQL. Данные для инициализации текущей витрины переносит миграция `0003`.

Проверка админки на локальном Compose (создаёт временный товар и изображения,
проверяет изменения витрины, восстанавливает витрину и удаляет только свои фикстуры):

```sh
python3 scripts/admin_smoke_test.py
```

Тест читает локальные учётные данные из `.env` или переменных окружения и не
выводит их. Проверяет авторизацию, CSRF, загрузку файлов, пустую карточку и необязательные фотографии,
создание/редактирование товара, актуальность кеша, витрину и отзыв сессии.

Поля товара необязательны: можно сохранить пустую карточку или одну фотографию без ярлычка. Неуказанные цена и год хранятся как NULL; ограничения длины, формата, цены и загрузки файлов сохраняются.

### Аккаунты покупателей

`/account` открывает регистрацию и вход по логину и паролю. Регистрация требует логин (3–40 букв, цифр, точек, дефисов или подчёркиваний), пароль (не менее 8 символов) и его подтверждение. Логины уникальны без учёта регистра; логин администратора зарезервирован. После регистрации пользователь автоматически входит в аккаунт.

Пользователи сохраняются в `customers`; пароли хешируются Argon2, сессии хранятся в `customer_sessions` с хешем токена и сроком 7 дней. Cookie `tt_customer` — HttpOnly, SameSite=Strict; Secure включается через существующую настройку `COOKIE_SECURE`. Пользовательские сессии не дают доступа к API администратора. API: `/api/auth/register`, `/api/auth/login`, `/api/auth/session`, `/api/auth/logout`. Выход требует CSRF-токен.

Проверка: `python3 scripts/customer_smoke_test.py` создаёт временного пользователя и удаляет его после проверки.

### Чаты по товарам

У покупателя кнопка «Написать» открывает модальное окно; повторное открытие возвращает тот же диалог по товару. Список переписок доступен в аккаунте. В админке раздел «Чаты» показывает покупателя, товар и последнее сообщение; список обновляется каждые 5 секунд. Сообщения и индикатор набора передаются по WebSocket. Enter отправляет сообщение, Shift+Enter переносит строку. Текст ограничен 4000 символами, вложения не предусмотрены.

Миграция `0006_chats.sql` создаёт `chats` и `chat_messages`. История сохраняется в PostgreSQL; последние 100 сообщений загружаются при подключении, более ранние — кнопкой «Предыдущие сообщения». При обрыве связи клиент переподключается; идентификатор сообщения защищает от дублей. Удаление товара сохраняет переписку и снимок его названия/номера. Покупатель получает только собственные чаты, администратор — все; сессия проверяется при подключении, отправке, получении событий и каждые 15 секунд. WebSocket требует точного Origin из `APP_ORIGIN`.

WebSocket endpoints: `/api/auth/chats/ws?chat_id=…`, `/api/admin/chats/ws?chat_id=…`. Nginx и dev proxy настроены на Upgrade. Между соединениями одного процесса события передаются через Tokio broadcast; перед запуском нескольких реплик backend потребуется общий транспорт событий (например, Redis Pub/Sub).

Проверка: `node scripts/chat_smoke_test.mjs` (после `npm ci` в `front`). Создаёт временные товары/аккаунты, проверяет обмен по WebSocket в обе стороны, набор текста, права, восстановление и пагинацию истории, отсутствие дублей и отзыв сессии; затем удаляет свои данные.

Уведомления приходят обоим собеседникам на любой странице после входа: администратору через `/api/admin/chats/events`, покупателю через `/api/auth/chats/events` только для его переписок. Тост содержит ссылку на диалог. Звук воспроизводится общим HTML-аудиоплеером после взаимодействия с браузером, включая завершённое касание на телефоне. В меню есть кнопки «Включить звук» и «Проверить звук»; отключение звука сохраняется в браузере. До первого разрешённого браузером взаимодействия звук может быть заблокирован, тосты при этом работают. При переподключении загружаются последние пропущенные уведомления (до 100). Звуковые и визуальные уведомления предназначены для открытого сайта, не заменяют системные push-уведомления при закрытом браузере.

Проверка уведомлений и изоляции переписок: `node scripts/chat_smoke_test.mjs` (запущенный Docker Compose). Проверка активации звука, блокировки autoplay и сохранения настройки: `node scripts/notification_sound_test.cjs` (после `npm ci` в `front`).

На мобильных устройствах чат занимает видимую область экрана, учитывает появление клавиатуры и блокирует прокрутку фоновой страницы. При задержке подключения свыше 10 секунд выполняется повторная попытка; истёкшая сессия и недоступный чат показываются отдельно.
